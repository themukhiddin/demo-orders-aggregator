# Проверка daily-totals по сырым данным

Скрипты, которыми проверялся результат (см. `SOLUTION.md`). Эталон считается независимо от кода сервиса:
- заказы берутся из внешнего API напрямую;
- вебхуки перехватываются своим приёмником;
- дни считаются через `Intl` в таймзоне клиента на момент заказа.

Перед запуском окружение должно быть поднято по README проекта: загружен образ, выполнен `npm install`, создан `.env`.

```bash
scripts/verify/run.sh                         # c_7, 2026-03-27..2026-03-31, 3 прогона
CUSTOMER=c_7 FROM=2026-03-01 TO=2026-03-31 RUNS=5 scripts/verify/run.sh
```

**Внимание:** `run.sh` и `scenario.sh` пересоздают контейнеры `docker compose` этого проекта вместе с томами. Данные локальной БД удаляются: так получается «чистая БД» из регламента.

| Скрипт | Что делает |
|---|---|
| `run.sh` | Всё вместе: выгрузка → перехват вебхуков → эталон → N прогонов сценария со сравнением, плюс сверка `result.json` |
| `crawl-orders.mjs` | Выгружает все заказы из `/orders` с логом страниц (rate limit, конец пагинации) |
| `capture-webhooks.mjs` | Принимает вебхуки вместо сервиса, отвечает с задержкой и печатает максимум одновременных запросов |
| `expected.mjs` | Эталон `daily-totals`: версия из `/orders` плюс самые свежие версии из вебхуков |
| `scenario.sh` | Сценарий из TASK.md: чистая БД → сервис → `POST /sync` → вебхуки → `daily-totals` |

Результаты пишутся в `scripts/verify/out/` (в git не попадают).
